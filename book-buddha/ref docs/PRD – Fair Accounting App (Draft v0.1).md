# Product Requirements Document (PRD) – Fair Accounting App (Draft v0.1)

Working title: Book Fair Accounting App · Draft prepared 30 Oct 2026

## 1. About this draft

This draft is built only from the two chat files you uploaded. Both files contain **your messages only**; my earlier questions are missing, so a few answers cannot be matched to a question. Those are listed in Section 7 as open items. Nothing below has been added from outside your messages.

## 2. Product vision

- You want to build a **real, working SaaS product** (not just a personal project). If it gets built, you may give it away, donate it or sell it.
- It works like QuickBooks Online (QBO), but is organised **fair-wise**. In QBO terms, a fair is a hybrid of a *customer* and a *location*.
- A school may have **multiple branches**.

## 3. Users and language

- Users maintain their own accounting data, as they would in QBO.
- Interface language: **English only**.

## 4. Confirmed requirements

| Area | Decision |
| --- | --- |
| Fair structure | Every fair carries a **host school**. You called this a basic, good functionality. |
| Tracking | Track balances and activity **fair-wise** (customer + location hybrid), like QBO's customer, location or department tracking. |
| Schools | A school can have multiple branches. |
| Customer details | The app must maintain customer details. |
| Free books | Handled on a **percentage basis**, as agreed with the school and **entered by the user**. |
| Accounting logic | Accounting principles and custom accounting logic are **maintained by the user**; the app does not enforce them. |
| Notes | A notes section where users record any specific notes. |
| Custom fields | Users can add extra fields. **No limit** on these. |
| Data editing | Records can be **edited or deleted**. |
| Data safety | **Export and backup** are both needed. |
| Expected volume | "Bills maybe around 500 (500–1000 range)". See open item on what this counts. |
