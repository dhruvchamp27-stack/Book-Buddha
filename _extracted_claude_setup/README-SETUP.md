# Claude Code setup - portable bundle

Exported 2026-11-13 from `C:\Users\Dhruv Champaneria` (Windows 11).
This bundle rebuilds the way Claude behaves, the rules it follows, and the custom
skills (slash commands) on a different PC.

It does NOT contain any password, API key, or login token. See `MANUAL-STEPS.md`
for the handful of things you have to set up by hand.

---

## What is actually in here

Your setup has three layers. Claude reads all three and stacks them, most
specific winning.

### 1. `global/` - applies to EVERY project on the PC

| File / folder | What it does |
|---|---|
| `CLAUDE.md` | Your 5 core behaviour rules: one small step at a time, explain WHY/WHAT/RISK/HOW TO VERIFY, never overwrite without approval, ask before destructive commands, don't touch files outside the project folder |
| `settings.json` | Model (`claude-opus-5`), effort level, dark theme, fullscreen. Also the long `skillOverrides` list that turns ~80 unused built-in skills **off** so they stop cluttering your sessions |
| `skills/` | Your 5 personal skills: `session-start`, `session-end`, `handoff`, `hybrid-explain`, `resume` |
| `commands/` | Two older slash commands (`handoff`, `resume`) kept for compatibility |
| `hooks/` | Four PowerShell hooks - approval gate, command logging, protected-folder guard, session-context loader |
| `config/harness.config.json` | The generic harness rules: which folders are protected, which commands need approval |
| `plugins-registry/` | A record of WHICH plugins you use (Superpowers, Headroom) and where they come from. The plugin code itself is not copied - it re-downloads |

### 2. `teamd/` - the TeamD-Git umbrella folder

`CLAUDE.md` describing who Team D is, the folder map (`notes/`, `automation/`),
the naming conventions (`YYYY-MM-DD_short-slug.md`), and the hard rules about
secrets. Plus three shared skills (`cleanup`, `handoff`, `resume`).

### 3. `ac-automation/` - the invoice-pipeline project

| File / folder | What it does |
|---|---|
| `.claude/CLAUDE.md` | The real working contract - git gating (branch `Dhruv` only, never `main`), the announce-before-commit rule, session startup checks, the scratch-session rule |
| `.claude/skills/` | 6 project skills: `session-start`, `session-end`, `cleanup`, `hybrid-explain`, `i-have-adhd`, `warm-context-analysis` |
| `.claude/hooks/` | `session-context-hook.ps1` (auto-loads HOTcontext at startup), `protect-files.py` + `protected-files.txt` (blocks reads of config.json / .env / xlsx), approval and logging hooks |
| `.claude/config/harness.config.json` | The hard-block regex list - `rm -rf`, `git push --force`, `git reset --hard`, `git clean -fd` are refused outright |
| `.mcp.json` | Wires in the Codebase-Memory MCP server |
| `settings.local.json.example` | Headroom routing - machine-specific, see MANUAL-STEPS |

### 4. `memory/`

Claude's saved long-term notes for the AC_Automation project - `MEMORY.md` is the
index, the other files are one fact each.

## How to install on the new PC

Do these in order. Replace `<YOU>` with the Windows username on the new machine.

**Step 1 - install Claude Code itself.** If it is not already there, install it
and run `claude login` once in a terminal.

**Step 2 - put the global layer in place.**

Copy the contents of `global/` into `C:\Users\<YOU>\.claude\`, so you end up with:

```
C:\Users\<YOU>\.claude\CLAUDE.md
C:\Users\<YOU>\.claude\settings.json
C:\Users\<YOU>\.claude\skills\...
C:\Users\<YOU>\.claude\commands\...
C:\Users\<YOU>\.claude\hooks\...
C:\Users\<YOU>\.claude\config\...
```

Do NOT copy `plugins-registry/` into `.claude\plugins\` - it is reference only,
read it in Step 5.

**Step 3 - put the TeamD umbrella in place.**

Copy `teamd/CLAUDE.md` to the top of your TeamD-Git folder as `Claude.MD`, and
`teamd/.claude/` into `TeamD-Git\.claude\`.

**Step 4 - put the project layer in place.**

Copy `ac-automation/.claude/` into `TeamD-Git\AC_Automation\.claude\`, and
`ac-automation/.mcp.json` into the AC_Automation folder root.

**Step 5 - reinstall the plugins.** Open Claude Code and run:

```
/plugin marketplace add anthropics/claude-plugins-official
/plugin install superpowers@claude-plugins-official
```

Headroom is optional (it compresses long sessions to save tokens) - see
MANUAL-STEPS if you want it.

**Step 6 - restore the memory.** Claude stores memory per project, in a folder
named after the project path. On the new PC the path will differ, so let Claude
create the folder on first run, then copy the files from `memory/` into:

```
C:\Users\<YOU>\.claude\projects\<auto-generated-project-id>\memory\
```

Easiest way: start a session in the project and ask Claude
"show me the full path of your memory folder for this project", then paste the
files in.

**Step 7 - verify.** Start Claude Code inside AC_Automation and type
`/session-start`. If the setup took, you will see the HOTcontext briefing
automatically. Then type `/` and confirm your skills are listed:
`session-start`, `session-end`, `cleanup`, `hybrid-explain`, `i-have-adhd`,
`warm-context-analysis`.

## What will NOT be the same, and why

- **Past conversations are gone.** Session transcripts were deliberately left out -
  they are large and contain real vendor and property names.
- **Absolute paths.** Several hooks and configs name
  `C:\Users\Dhruv Champaneria\...`. If the new username differs, search the
  copied files for that string and fix it. The two `.example` files already have
  it replaced with `<YOUR-WINDOWS-USER>`.
- **Codebase-Memory index.** It lives in
  `%USERPROFILE%\.cache\codebase-memory-mcp` and must be rebuilt on the new PC.
